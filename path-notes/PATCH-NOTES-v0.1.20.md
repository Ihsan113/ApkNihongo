# NihonGo v0.1.20 — Native Missions (Misi Harian)

**Source base:** `NihonGo-Native-Android-v0.1.19-WebHandGestures.zip`.

**Reference:** `nihongowebmasalah.zip/client/src/screens/MissionsScreen.jsx`, three assets in `client/public/missions`, route mapping in `client/src/App.jsx`, and server implementation in `server/src/core/context.js` and `server/src/routes/wallet.js`.

## Changes

- Home's `missions` destination now opens an independent native `NativeMissionsScreen` built with Jetpack Compose and `LazyColumn`. No WebView or dummy mission list.
- Web's header, refresh, hero mission progress, credit balance, daily credit cap, 10-minute study timer, 3 daily statistics, six mission rows and reset notice are re-created with similar sizes and color palette.
- Reuses and converts the web's `mission-hero.png`, `mission-timer.png` and `mission-reset.png` to smaller transparent WebP resources. Background illustrations do not increase card height because they are drawn inside `matchParentSize` layers.
- Mission state comes from `/api/missions/today`: uses `baseClaimedCount`, `baseRequiredCount`, `daily.missionStudySeconds`, `daily.lessonsDone`, `daily.missionQuizCount`, balance, credit claim cap, and per-mission eligibility from the server.
- Claim sends POST `/api/missions/claim` through existing authenticated `AuthRepository`; the returned response replaces current data atomically. During failures, fetches server state to avoid displaying stale claims without faking success. Claiming state disables repeated taps.
- Preserves distinctions between claimable, completed/claimed, locked, bonus locked and review-not-available. Bonus is not manually unlockable. XP/credit amounts shown after claiming use the server's actual claimed amounts.
- Back, refresh, loading placeholders, network error and empty states; also refresh on app resume.
- Tapping study/lesson opens the native Learn destination. Quiz and Review show clear limitations rather than claiming fictitious activity: the corresponding native players do not exist in the current base. These are **not** silently marked complete.
- Does not alter Home's avatar/lip-sync/gestures, Login, Settings, admin or payment screens.
- Version code/name bumped to 20 / `0.1.20`.

## Test checklist after CI build

1. Open Home → Reward Center → Misi. Confirm its header, 3 images, six cards and bottom notice match the website on the same account, time and theme.
2. Try Daily Check-in → Klaim exactly once. Verify returned XP/credits, the claimed badge, Home balance and credit history. Ensure second tap does not claim twice.
3. Check progress `00:00 / 10:00`, lesson count, quiz count and daily limit against web. They must be fetched from backend, not generated by a timer while idle.
4. Verify optional review status `Belum ada soal` if no active wrong answers, and bonus stays locked until required base missions have been claimed.
5. Test refresh and opening the app after backgrounding it; test server offline and expired token errors.
6. Scroll to the end and back; verify the UI keeps up at 320dp, 360dp and 393dp, in portrait with system text size 1.3×.
7. Check the rest of Home (3D Sensei, TTS, hand motion, Reward Center) remains unchanged.

**Validation available here:** source-vs-web API contract inspection, basic Kotlin syntax tokenization and ZIP integrity. **Not available:** full Android Gradle build, emulator/device runtime screenshot and measured FPS. This release is source for the user to build through GitHub Actions.
